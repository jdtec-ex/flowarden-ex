# Sniffnet 与 Flowarden 第一阶段功能对照矩阵

## 1. 文档目的

这份文档用于回答一个非常具体的问题：

> Flowarden 第一阶段在去掉 `iced UI`、只保留 `CLI + headless core` 的前提下，是否遗漏了 Sniffnet 中对“流量获取与基础分析”真正重要的功能。

判断原则：

1. 只对照 Sniffnet 中与第一阶段目标相关的能力。
2. GUI 专属能力不要求第一阶段保留。
3. 深度解析、会话重建、复杂增强能力允许后置。
4. 对“看似不显眼但实际影响正确性”的运行语义，优先保留。

---

## 2. 结论摘要

结论分三层：

### 2.1 第一阶段必须保留，不能丢

1. 统一 live/offline 抓包抽象
2. BPF 过滤
3. 关键链路类型支持
4. 轻量 L2/L3/L4 解析
5. 流量方向判定
6. 服务识别启发式
7. 按秒聚合
8. offline 以 `pcap` 时间戳推进时间轴
9. `dropped_packets` / `last_packet_timestamp`
10. pause/resume 核心能力

### 2.2 第一阶段建议保留，但可作为阶段一.1

1. 实时抓包同时落盘 `pcap`

### 2.3 第一阶段可明确后置

1. rDNS
2. 国家/ASN 增强
3. 进程识别
4. 程序图标
5. GUI 图表与页面
6. 通知系统
7. payload 深解析
8. 会话级重建

结论判断：

> 按当前细化方案，第一阶段主线没有遗漏 Sniffnet 中对“流量获取与基础分析”最重要的能力，但必须继续把若干容易被简化掉的语义视为硬要求，而不是“实现时看情况”。

---

## 3. 功能对照矩阵

| Sniffnet 功能/能力 | 第一阶段是否保留 | Flowarden 第一阶段保留方式 | 说明 |
| --- | --- | --- | --- |
| 实时设备抓包 | 保留 | `capture` + `runtime` | 核心能力，必须有 |
| 离线 `pcap` 导入 | 保留 | `capture source` 统一为 device/file | 核心能力，必须有 |
| live/offline 共用分析链路 | 保留 | `CaptureRuntime -> decode -> classify -> aggregate` 单链路 | 这是 Sniffnet 的关键设计之一 |
| BPF 过滤 | 保留 | 在 `CaptureContext` / runtime 层统一应用 | 不能因为 CLI 化而丢失 |
| 关键链路类型识别 | 保留 | `LinkTypeEx` + decoder 分派 | 至少覆盖 `Ethernet/RawIp/IPv4/IPv6/LinuxSll/LinuxSll2/Loop/Null` |
| 轻量头部解析 | 保留 | `analysis/decoder.rs` | 第一阶段的分析核心 |
| 流量方向判定 | 保留 | `analysis/direction.rs` | 不能退化成简单“源 IP 是否本机” |
| loopback 特判 | 保留 | `direction` 规则的一部分 | 会影响统计和远端选择 |
| 离线模式方向回退策略 | 保留 | `direction` 中单独处理 | 这是 live/offline 一致性的关键 |
| 服务识别 | 保留 | `analysis/service.rs` | 但收敛到常见服务即可 |
| 服务识别启发式 | 保留 | 协议 + 源端口 + 目标端口 + 方向联合判断 | 不能退化成只看目标端口 |
| 按秒聚合 | 保留 | `flow/aggregator.rs` | 不能退化成逐包打印 |
| 实时 tick 推进 | 保留 | wall clock 驱动 flush | 与 Sniffnet 一致的统计思路 |
| offline 时间轴推进 | 保留 | 按 `pcap` 时间戳推进 tick | 很关键，之前最容易被忽略 |
| offline gap 表达 | 保留 | aggregator 处理跨秒空洞 | 用于还原离线时间轴 |
| `dropped_packets` | 保留 | snapshot 字段 | 属于抓包质量指标 |
| `last_packet_timestamp` | 保留 | snapshot 字段 | 属于抓包质量指标 |
| pause/resume | 保留核心能力 | runtime 层保留，CLI 首版入口可后置 | 不应从核心消失 |
| savefile 导出 | 建议保留 | live capture 可选同时写 `pcap` | 可作为阶段一.1，但不应架构阻断 |
| GUI 页面系统 | 不保留 | 第二阶段 Avalonia | 不属于第一阶段范围 |
| 图表展示 | 不保留 | 第二阶段 Avalonia | 不属于第一阶段范围 |
| 搜索/分页式 Inspect 页面 | 不保留 UI 形态，保留数据基础 | 第一阶段输出 `snapshot` / top summaries | 先保留数据，不保留页面 |
| rDNS 主机识别 | 后置 | 阶段二后或阶段三前按需要引入 | 对第一阶段正确性不是硬依赖 |
| MMDB 国家/ASN | 后置 | 后续 enrichment plane | 同上 |
| 进程识别 | 后置 | 后续扩展 | 平台相关且会放大复杂度 |
| 程序图标 | 后置 | 不纳入第一阶段 | 明显 UI 相关 |
| 通知系统 | 后置 | 不纳入第一阶段 | 可等基础链路稳定后再做 |
| payload 深解析 | 后置 | 第三阶段 | 与 YAGNI 一致 |
| 会话级重建 | 后置 | 第三阶段 | 与 YAGNI 一致 |

## 4. 第一阶段最容易“看似没丢，实际已弱化”的点

下面这些是评审时最需要盯住的点。

### 4.1 offline 回放时间语义

错误做法：

- 读取离线 `pcap` 时，按文件读取速度直接输出结果

正确做法：

- 按 `pcap` 包时间戳推进 tick
- 跨秒要 flush
- 必要时表达 gap

如果这里做错，虽然“功能看起来存在”，但已经不是 Sniffnet 那种可用于真实时间轴分析的离线模式了。

### 4.2 方向判定被过度简化

错误做法：

- 只要 `src_ip` 命中本机就是出站，否则就是入站

正确做法：

- 结合本机地址、loopback、未分配地址、offline 回退策略综合判断

如果这里做错，后续 top host、top service、连接方向统计都会歪。

### 4.3 服务识别被过度简化

错误做法：

- 永远优先看目标端口

正确做法：

- 至少结合协议、源端口、目标端口和方向

如果这里做错，很多客户端临时端口和服务端口的归因会错。

### 4.4 聚合退化成终端打印

错误做法：

- 每来一个包就直接打印一行

正确做法：

- 逐包分析
- 秒级聚合
- 输出 `TickSnapshot`

如果退化成逐包输出，就失去了 Sniffnet 核心设计里最重要的那层“聚合优先”。

### 4.5 抓包质量指标消失

错误做法：

- 只输出 totals，不输出丢包与最后包时间

正确做法：

- `dropped_packets`
- `last_packet_timestamp`

如果这些字段不保留，排障能力会明显下降。

---

## 5. 第一阶段不保留哪些 Sniffnet 能力，是合理的

下面这些能力即使第一阶段不做，也不算“丢失重要功能”，因为它们不属于当前阶段目标。

### 5.1 GUI 相关能力

1. 页面导航
2. 图表
3. 可视化组件
4. 设置面板
5. 缩略模式

原因：

- 这是第二阶段 Avalonia 的职责，不是第一阶段 CLI 的职责。

### 5.2 异步增强能力

1. rDNS
2. 国家/ASN
3. 程序识别
4. 程序图标

原因：

- 这些是增强层，不是基础分析闭环的前提。
- 现在做会把排期和复杂度明显拉高。

### 5.3 深度分析能力

1. payload 内容语义化
2. 会话重组
3. 高级协议解析

原因：

- 这本来就被规划在第三阶段。

---

## 6. 我建议作为“第一阶段硬门槛”的 Sniffnet 核心能力

如果你要做评审拍板，我建议把下面 8 项写成第一阶段不可妥协项：

1. live/offline 共用一条分析链路
2. BPF 过滤存在且可用
3. 关键 link type 存在且可用
4. 方向判定保留 Sniffnet 关键启发式
5. 服务识别保留方向感知启发式
6. 按秒聚合存在且稳定
7. offline 回放按 `pcap` 时间戳推进
8. `dropped_packets` 和 `last_packet_timestamp` 进入输出模型

这 8 项如果缺任意一项，第一阶段虽然“能跑”，但已经不是对 Sniffnet 核心能力的正确承接。

---

## 7. 最终判断

最终判断如下：

1. 当前第一阶段方案没有遗漏 Sniffnet 中对基础流量获取与分析真正重要的主干能力。
2. 真正需要警惕的不是“有没有写到”，而是实现时是否把一些关键语义偷简化了。
3. 第一阶段最该强盯的不是功能数量，而是：
   - offline 时间轴
   - 方向判定
   - 服务识别
   - 按秒聚合
   - 抓包质量指标

如果这几项守住了，Flowarden 第一阶段就是在“借鉴 Sniffnet 核心能力”的前提下做了一个更清晰、质量更高、也更符合后续演进的 headless core。
